Env Challenges

The "Works on My Machine" Problem

Inconsistent environments across development, testing, and production lead to unpredictable bugs and deployment failures.

Common Environment Challenges

  • ›Subtle differences in OS packages, libraries, or runtimes.
  • ›Difficulties reproducing bugs found only in specific environments.
  • ›Manually configured, poorly understood legacy systems.

Docker bundles the environment with code, creating a single, sealed artifact.

Containers vs VMs

Efficiency at the Process Level

Containers are lightweight, process-level isolates that share the host OS kernel, making them faster and more efficient than full VMs.

What is a Container?

  • ›Standardized package bundling code with environment.
  • ›Runs identically on any machine with an engine.
  • ›Leverages namespaces for process isolation.

Docker Concepts

Images, Containers, and Layers

Docker images are immutable, layered recipes that define read-only environments, from which running containers are instantiated.

Key Lifecycle Stages

  • ›Image: Immutable read-only snapshot.
  • ›Container: A running, isolated instance.
  • ›Layers: Cached, stacked base components.

Gains

No drift, Fast onboarding, isolation.

Pains

Learning curve, image bloat, ephemerality.

The Image (Recipe)

A blueprint created by a Dockerfile. It contains everything needed to run: code, runtime, system tools, and libraries.

The Container (Run)

The active execution of an image. You can start, stop, move, and delete them. They are ephemeral by nature.

The Registry (Storage)

Central storage like Docker Hub or GitHub Container Registry where images are versioned and shared.
GMS Strategy

GMS Infrastructure Blueprint

Containerization provides GMS with consistency and resilience by standardizing environments and managing dependencies via a shared base image strategy.

GMS Build Strategy

  • ›Shared gms-base for SQLAlchemy, Celery, and shared code.
  • ›Lean Service images inheriting from base.
  • ›Optimized build times via Docker layer caching.

Battle Scars: Apple Silicon crashes and OOM Exit 137 taught us the value of cgroup resource boundaries and health checks.

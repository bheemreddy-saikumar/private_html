Security Bedrock

IAM: The Security Bedrock

Identity and Access Management (IAM) is a crucial security framework ensuring that only the right entities access the right resources at the right time for the right reasons.

IAM is a Framework

  • ›Not a single feature, but a comprehensive set of policies and technologies.
  • ›Dictates how users and services interact with system resources.
  • ›Ensures correct entities access appropriate resources, at opportune moments, for legitimate purposes.

Key Distinctions

  • ›**Authentication (AuthN):** Verifies *who* you are.
  • ›**Authorization (AuthR):** Determines *what* you can do after identity is verified.

Authentication (AuthN)

Verifies the identity of a user or system attempting to access a resource. Answers "Who are you?".

Authorization (AuthR)

Determines what actions an authenticated user is allowed to perform on a resource. Answers "What can you do?".

IAM Flow

The Standard IAM Flow

A typical IAM flow involves a client initiating a request, undergoing authentication, receiving an identity assertion, and then undergoing authorization against defined policies.

IAM Request Lifecycle

  • ›1. **Identification Request:** Client presents identifying attributes (username, client_id).
  • ›2. **Challenge & Authentication:** System verifies identity via password, MFA, or signature.
  • ›3. **Identity Assertion:** Upon success, a digitally signed token confirms authenticated identity (e.g., 'user_id: 123').
  • ›4. **Policy Evaluation & Authorization:** Assertion is checked against access control policies for requested resource/action.
  • ›5. **Access Grant or Denial:** Request is permitted or denied (e.g., HTTP 403).

Centralization

Why Centralize IAM?

Centralized IAM is critical for enterprise systems to maintain a single source of truth, enable effective auditing for compliance, and enforce the principle of least privilege.

Single Source of Truth

Provides a unified view of identities and their access rights across the organization.

Audit & Compliance

Simplifies tracking who accessed what, when, facilitating compliance with regulations.

Least Privilege

Enables granular control, ensuring users only have the minimum necessary permissions.

Unified Identity

Centralized management reduces complexity and ensures consistency.

Simplified Auditing

Easier to track access logs for compliance and security reviews.

Effective Least Privilege

Granular permission assignment minimizes exposure to threats.

Boundaries

IAM System Boundaries

IAM acts as a gatekeeper at the service perimeter for initial validation and within individual services for fine-grained, business-specific authorization.

IAM Interaction Points

  • ›**Perimeter:** API Gateway or dedicated Auth service validates identity assertions (tokens).
  • ›**Service Layer:** Individual microservices enforce specific, business-driven authorization rules (e.g., manager role for specific actions).

Components

IAM Components & Revocation

Effective enterprise IAM relies on defining principals, resources, actions, and policies, while also addressing the critical challenge of timely access revocation.

Core IAM Components

  • ›**Principal:** Entity requesting access (user or service)
  • ›**Resource:** Data or service being accessed
  • ›**Action:** Operation intended by the principal
  • ›**Policy:** Rule governing Principal-Resource-Action interaction

Revocation Challenge

  • ›Disabling access for de-provisioned users or compromised keys is difficult in distributed systems.
  • ›Mechanisms like token expiration and dynamic revocation lists are needed.
  • ›Access denials must propagate in near real-time.

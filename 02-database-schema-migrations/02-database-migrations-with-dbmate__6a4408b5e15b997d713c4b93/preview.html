Alembic Intro

What is Alembic?

Alembic is the version control system for your database, built on SQLAlchemy to manage schema changes via Python scripts and ensure consistent database states across environments.

Manual SQL scripts lead to schema drift; Alembic prevents this.

Alembic's Role

  • ›Version control for database schemas.
  • ›Built on SQLAlchemy.
  • ›Defines schema changes in Python scripts.
  • ›Ensures consistent database states.

The Solution Pattern

Manual SQL Drift

Dev A adds a column, Dev B misses it. Production breaks due to mismatch.

Alembic Solution

Synchronized Python scripts ensure every environment mirrors the exact same schema state.

Configuration

Alembic Configuration Files

Alembic's behavior and database connection are defined by alembic.ini for global settings and env.py for runtime environment configuration.

alembic.ini

  • ›Global configuration file.
  • ›Defines script path and logging.

env.py

  • ›Executes on invocation to setup engine.
  • ›target_metadata links models to DB.

alembic.ini

script_location = migrations

sqlalchemy.url = driver://user:pass@host/db

env.py

target_metadata = MyModel.metadata

This variable is crucial for autogenerate to compare code vs. DB.

Script Structure

Migration Script Structure

Each migration script, identified by a unique version ID, contains upgrade() and downgrade() functions to manage database schema changes and their reversals.

Atomic Idempotent & Reversible

Migrations must be reversible; downgrade must perfectly undo upgrade.

Revision ID

e.g. 7f83a21b4592 - Unique file identifier.

upgrade()

op.add_column('user', Column('bio', String))

downgrade()

op.drop_column('user', 'bio')

Management Workflow

Alembic Management Workflow

The Alembic CLI streamlines database management through commands like revision --autogenerate for script creation and upgrade head for applying the latest schema changes.

Generating Revisions

  • ›revision --autogenerate compares models to DB.
  • ›Generates upgrade and downgrade logic.
  • ›Requires manual review of results.

Applying Migrations

  • ›alembic upgrade head syncs DB to latest.
  • ›alembic current shows active revision.
alembic revision --autogenerate -m "message"
alembic upgrade head
alembic current
alembic history

Migration vs Seeding

The DDL vs DML Boundary

Alembic is optimized for schema evolution (DDL), while initial data is better managed through a separate seeding process.

Alembic's Focus

  • ›Optimized for Schema Evolution (DDL).
  • ›Bulk insert possible but discouraged for large sets.

Alembic manages the structure; seeding manages the foundational content.

SCHEMA (DDL) DATA (DML)

Alembic's Domain

Handles structural changes like CREATE TABLE, ALTER COLUMN, and INDEX management. Essential for code/database synchronization.
